# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

kloudlite — a terminal agent harness for cloud dev environments. Bun + Turborepo monorepo:

- `apps/tui` — the TUI (opentui/React), plus an SSH server that serves it
- `packages/agent` — wrapper over the pi SDK (`@earendil-works/pi-*`): models, auth, sessions
- `packages/tools` — provider-agnostic tool registry (`ToolDef`/`Registry`); ships **no** built-in tools

## Commands

```bash
bun install
bun run dev                    # turbo dev → apps/tui local TUI
bun run --cwd apps/tui dev     # same, directly
bun run serve                  # SSH server on :2222 (ssh -p 2222 anyone@localhost)
bunx turbo check               # tsc --noEmit across all workspaces
bun test                       # from apps/tui — bun:test
bun test src/slash.test.ts     # single file
bun test -t "sidebar renders"  # single test by name
```

## Architecture

**Agent layer** (`packages/agent/src/index.ts`). A single module-level `ModelRuntime` owns every provider, the model catalog, and credentials. Config lives under `~/.config/kloudlite/` (override with `KLOUDLITE_CONFIG_DIR`): `auth.json`, `models.json`, `settings.json` (defaultModel/theme/sidebar/thinking), `sessions/<key>/`, `host_key.pem`. `createSession({key, ...})` continues the most recent persisted session for that key unless `fresh`; `/clear` archives files instead of deleting them. Custom tools from a `Registry` are adapted into pi tool defs here.

**Sessions are hierarchical and independent** (`apps/tui/src/sessions.ts`). The hierarchy is **working session › main session › workspaces**: **every context holds named sessions** — the environment's main sessions and each workspace's own. `sessionBase(wsId?)` gives the context (`main` or the workspace id) — **the environment is not part of a session key**, so connecting elsewhere never swaps a transcript and `sessionKey(...id)` hangs a session off it (`<base>` for the default "main", `<base>:<id>` for named ones); `app.tsx` tracks `sessionId[base]`. Workspaces hang off a main session (`Workspace.session`), so switching main sessions swaps which workspaces are in view. A session's **title is inherited from what owns it, never derived from a prompt or from context**: the main session is always `Working Session`, a workspace's session is the workspace name, and an ephemeral one is its own agent name. `/session name` still names a session in `meta.json` for `/session use`, but the title bar does not read it. Titles and descriptions live in each session dir's `meta.json` (`nameSession`/`describeSession`/`listSessions` in the agent package) and are driven by `/session name|desc|new|use`. Every chat session is topped by a **title bar** (`components/SessionTitle.tsx`): the inherited title in bold, a dim subtitle under it **only** when `/session desc` set one (there is no derived subtitle — the workspace-and-changed-files line was removed), `working` on the right while a turn streams, and a hairline below. Clicking it opens `/session`. The subtitle deliberately does *not* repeat the environment path. The hint bar's context path is **just the workspace you are in** (`contextPath` in `app.tsx`) — at the main context it is `Working Session`, the same inherited name the title bar shows; the environment and main session are already in the sidebar. **Workspaces belong to the working session, not to an environment** (`MOCK_WORKSPACES`, `allWorkspaces` state in `app.tsx`) — an `Environment` carries only its services. So connecting elsewhere brings this exact list along and can never mix another session's or environment's workspaces in, and there is no move/attach verb: workspace actions are intercept, release and clone only. **One connected environment at a time** — no tabs, no open-env list: **The agent drives the lifecycle, not the user** — there is no actions menu and no `/env`, `/workspace`, `/intercept` or `/release` command; connecting, creating, cloning and intercepting are things the agent does. `connectEnv`/`newWorkspace`/`cloneWorkspace`/`interceptService`/`releaseInterception` survive in `app.tsx` as the shape those agent tools will call and are currently unreachable (marked `ponytail:`); the jump palette navigates workspaces only. Its services hang off it in the sidebar's Environment section. The sidebar (`components/Sidebar.tsx`) is modelled on a desktop-app layout and **docks on the right**. **Working session and environment are different things and are never mixed.** The header is the working session (`✦ Working Session`) and the `Workspaces` list under it belongs to it. The pinned bottom block is the environment: an `Environment` heading, the connected env's name, its services indented under it, and the restore point it is sitting on as the **last line of the block**, dim and labelled (`current snapshot: <name>`, from `Environment.snapshot`) — labelled because a bare name reads like a tag, and at the bottom because beside the env row it collides with a long env name; the agent takes and switches snapshots and the UI never lists them — Services belong to the environment, so they are **indented directly under it**. The services have no heading of their own; the indent is what says they are the env's. **Section headings are bold title-case followed by a hairline** that fills the rest of the row (`Heading` in `Sidebar.tsx`), the same separator the session title bar uses — no SHOUTING CAPS and no full-width rule above a heading, since the hairline already divides. **Every row is exactly one line** — a workspace's branch and change count are deliberately not shown (tried, too noisy); ephemeral workspaces appear by their own short `name` on `├`/`└` branches under their parent. Every agent is isolated by code, network and storage, and none of that surfaces in the sidebar. A service row keeps the accent on its own name when intercepted and puts `→ workspace` in the dim right-hand column ahead of `proto:port`, so ports stay aligned. No status dots or phase tags — rows are plain text; one state word (`working` while its session streams, `42%` cloning, an owner) sits on the right only when it matters. A turn keeps streaming in its own session while the user looks at another — never assume the visible session is the running one. `App` holds `SessionMap` state plus a `useRef` map of live `AgentSession` promises created lazily per key.

**UI** (`apps/tui/src/app.tsx`, ~1.1k lines — the whole keyboard/state machine). **Two key schemes, chosen by the `vim` setting** (`/settings vim on|off`, default **off**): with vim off the prompt is always live and the commands live on ctrl+<letter> (`^f` views, `^p` jump, `^q` queue, `^j`/`^k` cycle workspaces, `^1`-`^9` / `^0`, `?` help); with vim on the keyboard is modal — NORMAL takes those same commands as bare letters and `i` enters INSERT. Both share a `/` command overlay, a palette, and a Files review view. Agent events (`message_update`, `tool_execution_*`, `queue_update`, `compaction_*`, `auto_retry_*`) are translated into `Entry[]` for `Transcript`.

**Views**: `f` cycles chat › files › processes for the selected workspace (each view takes an `onCycle` prop so `f` works from inside it too). The files view holds both sections in one list — CHANGES (vs HEAD) above the FILES tree, reader pane on the right (`v` flips a changed file between its diff and its full contents — in the full view the line number goes green for a line added since HEAD and a red `── n deleted ──` rule marks where lines were removed, computed by `fullFile`/`marks` in `git.ts` from a `-U0` diff); the processes view (`components/Processes.tsx`) lists what the workspace runs and shows the selected process's output, same two-pane shape and keys. 

**Mouse works everywhere it makes sense**: opentui exposes `onMouseDown` on any `box`, so tabs, sidebar rows (environment + workspaces), slash-menu and ask/permission options, hint-bar hints, files-view tree rows, change headers and search hits are all clickable; wheel scrolling comes from the `scrollbox`es. Tests drive it with `mockMouse.click(x, y)`.

**Responsive rule, copied from opencode** (`routes/session/index.tsx`): one breakpoint, `wide = columns > 120`. The sidebar is 42 columns by default and **resizable** — `[` / `]` in vim NORMAL, or `/settings width wider|narrower|reset`, step 4, clamped to 28..64 and persisted as `sidebarWidth` in `settings.json`. opentui exposes no drag stream, so the divider itself can't be dragged (marked `ponytail:`). At every size — wide terminals dock it on the right of the session column; narrow ones show it only when opened (`/settings sidebar show`) and then as an absolute overlay (right-aligned) over a dimmed transcript. The hint bar drops secondary hints when not wide.

**Layout must match opencode (sst/opencode) 1:1** — paddings, borders and the prompt card are ported from its source (`src/ui/border.ts` holds the SplitBorder chars). When the UI looks off, diff against opencode's source, not against a screenshot.

**The tree is exactly three levels**: main session › workspaces › ephemeral workspaces (spun off a workspace like a git worktree, `parent` set). Nothing nests deeper — `parentFor()` re-parents an ephemeral's clone onto its workspace, and `depthOf()` returns 0 or 1. The list stays flat and in tree order so `focus` keeps indexing it 1..N; `treePrefixes`/`wsPath` derive the guide characters and the context path.

**Mock data**: `apps/tui/src/workspaces.ts` is entirely placeholder (environments, workspaces, services, `CURRENT_USER`). Nothing there reflects real kloudlite semantics; expect it to be replaced wholesale.

**Queued messages** (`components/Queue.tsx`). Prompting while a turn streams queues the text in pi (steering interrupts, follow-up waits). `Session.queued` holds the real `QueuedMessage[]` (`{text, kind}`), not just a count, fed by the `queue_update` event. A **QUEUED** panel above the prompt lists them (`steer`/`after` per row); `^q` (or `q` in vim NORMAL) targets the list (or click `N queued` in the hint bar), then `j`/`k` pick, `enter` pulls one back into the prompt to re-edit, `d` drops it, `esc` leaves. pi has no per-item removal, so `rewriteQueue` clears the queue and re-queues the keepers in order onto the queue each kind names.

**Transcript scrolling** (`components/Transcript.tsx`). opentui's `scrollbox` with `stickyScroll` pins the bottom while a turn streams; PageUp/PageDown page, `u`/`d` half-page in vim NORMAL. Scrolling away reveals a centred **↓ jump to bottom** row under the transcript — clickable, or `end` (`G` in vim NORMAL). Long blocks **collapse like Claude Code's**: an agent message or bash output over 10 lines renders its **first** 10 (the head, so it still reads from the beginning) above a dim `… +N lines  ctrl+o to expand` row. That row stays once open, reading `ctrl+o to collapse`, so a block can always be put back — click it to toggle just that entry, or press `ctrl+o` (`o` in vim NORMAL) for every entry at once. `ctrl+o` is the master switch and clears the per-entry overrides, so one press really does move them all; a per-entry click is XORed against it (`openAll !== open.has(key)`). The scrollbox exposes no `onScroll`, so "am I at the bottom?" is sampled on a 200ms timer (marked `ponytail:`); that is also what catches wheel scrolling.

**Slash commands** live in `slash.ts` (`commands` list + `menuItems(input, ctx)` producing option rows); handlers are in `app.tsx`. The overlay's draft **always carries its leading `/`** — `openCmd` prefixes it, `menuItems` is given it verbatim, and picking an option-command keeps it. Typing `/` into an empty live prompt opens the overlay via `changeInput` (the prompt owns the key), so the slash the user typed is the slash in the draft; stripping it anywhere desyncs `Input`'s internal copy of the value and keys get doubled or eaten.

**Pasted images** (`apps/tui/src/clipboard.ts`). `ctrl+v` reads a PNG off the system clipboard into the `images` state; an attachment is **a token in the prompt value, not a chip beside it** — opencode's model (`packages/app/src/components/prompt-input/attachments.ts` inserts the part at the cursor). `ctrl+v` is handled **inside `components/Input.tsx`**, which owns the caret: `onPasteImage()` keeps the image in `app.tsx` and hands back an `[Image N] ` token, `Input` inserts it at the caret and moves the cursor past it, so pastes keep their place and typing continues after them. `Input` renders any `[Image N]` run in the value as an amber badge (bold `theme.bg` on `theme.warning`). The counter is a `useRef`, not `images.length`, because a burst of keys in one stdin chunk runs every handler against the same render. On submit the transcript entry keeps the tokens where they were typed and carries an `images` count that draws a `File`/`clipboard` badge pair under it, the label reading `N Files` when more than one is attached; the model is sent the text **with the tokens left in** — they are how it tells one attachment from another, and stripping them left an image-only message with empty text. `ctrl+v` refuses with an error entry when the session's model does not list `image` in its `input` (pi's `Model.input`), since a text-only model drops attachments silently; an unresolved model does not block the paste. A token is **one thing to the caret**: backspace over an `[Image N]` deletes the whole badge in one press, and left/right step across it whole (`tokenStart`/`tokenEnd` in `Input.tsx`), since deleting it a character at a time leaves a broken `[Image ` on screen. `readClipboardImage()` is **per-platform and tries both**: macOS has no way to get PNG bytes out of `pbpaste`, so AppleScript coerces the clipboard to `«class PNGf»`, writes it to a temp file, and we read it back and delete it; Linux (and the bench browser terminal's stand-in) uses `xclip -t image/png`. It never throws — a missing tool or a text-only clipboard is a silent no-op, so don't "simplify" it down to one platform's tool.

**Provider login** (`apps/tui/src/components/Login.tsx`). One generic component drives every provider — pi owns the flow, we only render what it emits, so all 40 providers share these 170 lines and none of them is special-cased. It covers pi's four `AuthPrompt` types (`text`, `secret` masked, `select` with arrow keys, `manual_code`) and all four `AuthEvent` types (`info` with its optional `links`, `auth_url` — printed *and* opened with `open`/`xdg-open`, `device_code`, `progress`). **Both abort signals matter**: the flow-level one from `AuthInteraction`, and `AuthPrompt.signal`, which pi fires when something else answers a step — a `manual_code` prompt raced against the OAuth callback server. Without the per-prompt listener the user keeps typing into a prompt that already resolved.

**The model catalog is dynamic** (`refreshCatalog` in `apps/tui/src/models.ts`). All 40 providers implement pi's `refreshModels`; the per-provider JSON in `pi-ai/dist/providers/data/` is only an **offline seed**, and a seed goes stale — the bundled one is stamped 2026-08-07 and still lists `deepseek-v4-flash`, an id DeepSeek no longer serves, while missing `deepseek-flash`, the only DeepSeek model that accepts images. `models.refresh()` fetches each *configured* provider's live list (~500ms, errors returned rather than thrown, unconfigured providers skipped) and persists it, so the next launch starts correct. `app.tsx` holds the catalog in state seeded from the import-time list: the seed paints at once and the live list swaps in, so the network is never on the paint path. It refreshes at startup **and after a successful `/login`**, since a login configures a provider the first refresh skipped. Don't go back to a module-level `const catalog` — a never-refreshed catalog is pinned to whatever shipped in `dist`, which silently costs both model ids and capabilities.

**`/model` shows only models you can run** (`menuCtx` in `app.tsx`, `/model` branch in `slash.ts`). The catalog is 1300+ models across 40 providers, so models whose provider has no credentials are filtered out — they are unreachable, and picking one only fails at request time. What's left is **grouped by provider and sorted within it**, with the model's display name in the hint (the label is already `provider/id`). Filtering creates a first-run dead end, so two things cover it: a `/model` menu with nothing to show **offers the logins instead** (rows insert `/login <provider> <type>`), and a mount-time check appends `No AI provider connected yet — run /login to connect one.` to the transcript when no provider resolves, since typing `/login` is not discoverable. Both matter — the notice is the one a first-run user actually sees. Note `auth.ok` means *a credential resolved*, not that it works: a dead key still reads as connected until a request fails.

**`DEFAULT_MODEL` trusts what was saved** (`models.ts`). It is computed at import, *before* the refresh, so the only models it can see are the seed's — validating a saved `defaultModel` against the catalog there discarded any model the seed predates, and a cold start silently replaced a saved `deepseek-flash` with the anthropic fallback. A saved choice is now returned unvalidated; a model the provider has since dropped surfaces as a request error, which beats losing the user's choice. `modelLabel` already falls back to the bare id for a model the catalog doesn't know.

**Provider env vars** (`envKeysFor` in `packages/agent/src/index.ts`). pi exports no provider-to-env-var mapping, but every provider resolves credentials through `ctx.env(name)` — so passing a context that records the names and returns nothing reports exactly what that provider reads, in preference order. Don't go back to guessing `${ID}_API_KEY`: it was wrong for 13 of 40 providers (Bedrock takes AWS credentials, Hugging Face `HF_TOKEN`, github-copilot `COPILOT_GITHUB_TOKEN`), which strands a user at the moment they are already stuck. An OAuth-only provider returns `[]`, and the model picker shows no hint for it.

## Terminal keyboard gotcha

The user runs WezTerm with the kitty protocol off. opentui's native setup writes `CSI >4;1m` (modifyOtherKeys mode 1), which keeps ctrl+h/ctrl+j as legacy bytes indistinguishable from Backspace. Both `cli.tsx` and `server.tsx` therefore re-assert mode 2 *after* startup — `cli.tsx` via `writeSync(1, ...)` because opentui patches and buffers `process.stdout`. Don't "clean up" those writes. Verify key fixes by capturing raw bytes (`tmux pipe-pane`).

## Testing

`bunfig.toml` preloads `src/test-setup.ts`, which points `KLOUDLITE_CONFIG_DIR` at a temp dir — without it tests write named sessions and settings into the real `~/.config/kloudlite`. `apps/tui/src/app.test.tsx` mounts the real `App` with `testRender` from `@opentui/react/test-utils`: drive it with `mockInput.pressKey/typeText`, assert on `captureCharFrame()` text. `mount()` writes `vim: "on"` into the temp config by default, so tests start in NORMAL mode and its `insert()` helper presses `i`; `mount({vim: "off"})` exercises the shipped insert-only default, where typing reaches the prompt straight away.

## Known ceilings (marked `ponytail:` in source)

- SSH server accepts any credentials (LAN dev tool); theme/settings are process-global, so concurrent SSH sessions share them.
