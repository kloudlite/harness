# Tools

One tool per resource. `action` picks the verb; the arguments below are the union over the actions, and a call that omits one an action needs is refused with that action's schema. `workspace` is a `ws-` id or a name of a `ready` workspace, `env` an `env-` id or a name. Create, fork, start and `run` start take `wait: true` and `soft_ms` (default 25000, 20000 on a remote door; at most 600000): they answer when the object has settled, or with `{promoted: true, id, kind}` at `soft_ms`; call the `wait` action of the tool named by `kind` (`netgroup`: `get`). A `wait` action takes `timeout_ms` (default 25000, at most 900000) and answers with `timed_out: true` at the limit: call it again. A remote door holds every wait to 20 s, or to 40 s for a client that asks for progress (it sends a `progressToken`; the door then streams `notifications/progress` every 10 s); a cut call carries a `clamped` note. `exec` and `container_build` hand off the same way with kind `process`: loop `process` `wait` with `since` and `since_err` set to the last `next` and `next_err`. A `process` `wait` on a finished process stays listed with its output readable for 24 hours (the latest 200); an id that ended before that or never existed answers `state: "gone"`. The loop applies when a `promoted` answer arrives; a client that waits on MCP tasks waits on its own and never sees one.

## Ids and states

| Object | Id starts with | States |
|---|---|---|
| Workspace | `ws-` | `creating`, `ready`, `stopped`, `error`, `deleted` |
| Environment | `env-` | `creating`, `running`, `stopped`, `error`, `deleted` |
| Netgroup | `ng-` | `running`, `idle`, `stopped` |
| Capsule | `cap-` | `phase`: `pending`, `starting`, `running`, `terminated`; with `reason` `Exited`, `exit_code` is the result |

Get ids from the `list` actions of `workspace` and `env`, or from `netgroup` `list`. Tools take the id or the name. A volume reference is `name@<tag>` (`shop-code@base`), `name@N` (a snapshot), `name` (its `base` snapshot, else its newest), or a snapshot id; nothing is checked out by any of them; workspace and env `fork` take one in `snapshot_id`, env `restore` in `source`, a capsule in `from_snapshot`. A netgroup goes `idle` after 30 minutes without use (a tool call, an open connection, or a running process in `process` `list`), and its workspaces stop; a start, a create in the netgroup or a connect wakes it, and the next tool answer reports each workspace restart and stop that happened while idle. What the user stopped stays stopped.
